# RC33 Windows installer packaging review — 2026-11-04

New packaging lives only in the isolated Windows installer worktree. It does not
change the macOS installer, CI workflows, RC33 application wheel or existing
Windows Dev Kit. No commit, push or publication is performed by the builder.

  Its original source is `ce0687dd8831dae261bf285922a146bcf3aedc41`.
- Official CPython 3.14.10 x64 **embeddable** ZIP SHA-256:
  `b553e7dac884469b40e0740bb527271c3378f700b427e0485835f1bb6424361c`.
  Download bytes match the `pythonembed-3.14-64` entry in the official
  [Windows release manifest](https://www.python.org/ftp/python/3.14.10/windows-3.14.10.json).
  The legacy `embed-amd64.zip` filename has different bytes and is rejected.
- Builder checks the fixed outer archives, all 50 Dev Kit checksum entries,
  Python PE architecture, safe extraction names, Windows case collisions,
  symlinks, expansion bounds and wheel destination collisions. It expands the
  original 38 wheels directly into a private runtime; no pip, Python installer,
  global registration, PATH change or new dependency resolution occurs.
- The private `python314._pth` limits imports to bundled paths and enables
  `site` for the original pywin32 `.pth` bootstrap. All maintenance and launcher
  commands use `-I -B` to avoid global paths and generated bytecode.
- Runtime release identity is a deterministic 32-character hex digest of the
  complete file map, including the installer lifecycle helper. Application
  source provenance and new lifecycle bytes are distinguishable.
- Inno Setup runs per user. It keeps a separately tracked maintenance runtime
  so uninstallation can remove application releases without deleting the
  interpreter executing the uninstall helper. An exact-file uninstall entry
  removes only the generated `.lifecycle.lock` after the helper exits; no wildcard
  uninstall deletion applies to user data. Prepare/commit/rollback/finalize are lifecycle actions;
  the only `[Run]` entry is an unchecked user launch after successful setup.
- Commit is the final file's `AfterInstall`, before Inno finalizes its uninstall
  log. Failure before successful completion invokes explicit lifecycle rollback.
  A persistent lifecycle journal is the recovery path after process/power loss.
  This is not a claim that Inno itself provides a database transaction or that
  every possible power-loss point has been natively tested.
- Production AppId is stable (`KiraBridge.Windows`). Native acceptance uses the
  exact production Setup after confirming its registration is absent, with
  separate application/data paths. The default `KiraBridge` Start-menu folder
  was proven newly created during the test and contains only its three links.
  `/GROUP` is ignored when the group page is hidden; the harness was corrected
  after initially looking for a nonexistent custom group. Windows 11 x64 is the
  documented product scope; no ARM build or acceptance is claimed.
- Setup and Uninstall atomically create the same per-user, session-local named
  mutex before lifecycle work. They retain its non-inheritable handle through
  finalization/rollback or uninstall cancellation. A second wizard fails closed
  rather than interpreting a live transaction as interrupted. Process termination
  closes the handle automatically; durable journal recovery remains available.
