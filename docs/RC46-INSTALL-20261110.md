## Installation (für den Organisator)

Im eigenen sichtbaren Terminalfenster ausführen. Vorher prüfen, dass 0 Tasks aktiv sind.
Die Config braucht keine Handänderung: `source_root` zeigt schon auf die bytegleiche
`threaddesk-aa940db`, der Installer übernimmt sie und stellt `command` auf RC46 um.

```sh
S="$HOME/.local/state/rc46-mac-20261110"
B="$S/package-check/extracted/KiraBridge"
shasum -a 256 "$S/artifacts/KiraBridge-macos.tar.gz"
# erwartet 7712bc6494ab95566fa46aebdd90676951263dfac2430e595bbed7d8e000aa2e
/usr/local/opt/python@3.11/bin/python3.11 "$B/installer/install.py" install \
  --bundle "$B" --desktop --require-visible-terminal
```

Readbacks danach:

- `current.json`, CLI `status` und MCP `bridge_health` melden 0.8.0rc46 und `releases/0.8.0rc46-f0068fbc039f`.
- Die Zusammenfassung zeigt „ThreadDesk threaddesk-aa940db“. In `~/.config/kirabridge/config.toml` zeigt
  `[threaddesk].command` auf `…/releases/0.8.0rc46-f0068fbc039f/source/.venv/bin/python`.
- In Kira heißen die Befehlswerkzeuge `td_library_usearch`, `td_whiteboard__*` usw. (kein `td_td_`).

## Danach: Claude-Bindung (P2/P3, einmalig)

Aus `~/.local/share/kirabridge/acceptance/P2P3-20261110.md`. In `~/.config/kirabridge/config.toml`
ergänzen, Werte aus `session_catalog()` für die Zeile mit `agent_candidate=claude` im Koordinator-Tab:

```toml
[visible_handoffs.bindings.claude]
pane_id = "terminal:<win>:ttys000"
expected_pid = <zsh-PID>    # heute 850
agent_pid = <claude-PID>    # heute 891
ready_pattern = "❯"
busy_pattern = "esc to interrupt"
```

Danach den Bridge-Dienst einmal neu laden. Ohne diese Bindung bleibt `session.input` zu Claude
absichtlich `visible_target_missing`.

## Danach: Kompaktierung der Live-DB (P0, optional, nur bei gestopptem Dienst)

```sh
PY="$HOME/.local/share/kirabridge/install/releases/0.8.0rc46-f0068fbc039f/source/.venv/bin/python"
DB="$HOME/.local/share/kirabridge/bridge.sqlite3"
BK="$HOME/.local/share/kirabridge/compaction-backup-$(date +%Y%m%d)"
# 1. Stopp (vorher 0 aktive Tasks)
launchctl bootout "gui/$(id -u)/com.kirabridge.bridge"
# 2. Probelauf, ändert nichts
"$PY" -m kirabridge.storage_compaction "$DB" "$BK"
# 3. Anwenden mit Backup; die Ausgabe nennt das Manifest compaction-<stempel>.json in $BK
"$PY" -m kirabridge.storage_compaction "$DB" "$BK" --apply
# 4. Start
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.kirabridge.bridge.plist"
# Rückweg (Dienst wieder stoppen):
# "$PY" -m kirabridge.storage_compaction "$DB" "$BK" --restore "$BK/compaction-<stempel>.json"
```

Nur abgeschlossene Aufgaben werden verkleinert. UNKNOWN, wartende und laufende Arbeit, Events,
Freigaben und die Audit-Kette bleiben bytegleich.

**Rückweg RC46:** Im sichtbaren Fenster mit demselben Paket:

```sh
/usr/local/opt/python@3.11/bin/python3.11 "$B/installer/install.py" rollback \
  --bundle "$B" --require-visible-terminal
```

`rollback` setzt `[threaddesk].command` auf das RC45-Python zurück (`source_root` war schon
`threaddesk-aa940db`). Eine angewandte Kompaktierung vorher mit `--restore` zurücknehmen, damit
RC45 wieder die vollständigen Ergebnisse liest.
